## 2. What the primary sources establish

1. **The PDK states model validity, not ratings (W1, L1).** `nfet_g5v0d10v5`:
   VDS 0 to 11.0 V, VGS 0 to 5.5 V, VBS 0 to -5.5 V. `pfet_g5v0d10v5`: mirrored
   (-11.0, -5.5, +5.5). `esd_nfet_g5v0d10v5`: VDS 0 to 11.0 V, VGS 0 to 5.0 V.
   Junction diodes: |V| 0 to 5.0 V, with no current or area range. Diode reverse
   breakdown is an e-test figure (N+ 11.7 V, range 10.7 to 14.0 V; P+ 12.2 V),
   and `bv` / `ibv` in the model files are fit parameters. No gate-oxide stress
   limit and no failure current was found anywhere.
2. **Model coverage is geometry-binned (L1).** The 5 V MOS models are binned from
   L = 0.5 µm, W up to 100 µm per instance. The `esd_nfet_g5v0d10v5` model exists
   but only at L = 0.55 µm with ten fixed W values (5.4 to 51 µm). Decision 0004
   previously named only `esd_nfet_01v8`; corrected.
3. **Foundry I/O cell facts (W2).** `gpiov2` VDDIO range 1.71 to 5.5 V (simulation
   range 1.65 to 5.5 V); over-voltage tolerance "No" (Table 101); rail-based ESD
   with an RC clamp per power domain, HV clamp time constant 2 µs, about 150 ohm
   at the core access; clamps stated "robust up to 3.3KV HBM" (the foundry's own
   statement). The guide gives no pad pitch and no widths.
4. **Latch-up (L2, W4).** SkyWater's tap-distance rule as transcribed in the Magic
   tech file: N-diffusion to P-tap `LU.2` < 15.0 µm; in deep n-well `LU.2.1`;
   P-diffusion to N-tap `LU.3` < 15.0 µm; 6 µm where the chip-top latch-up marker
   is absent. The BAG3 file's 3000 / 1200 grid units at 0.005 µm give 15 / 6 µm,
   agreeing. No source states an I/O-to-core well spacing or a guard-ring
   construction rule.
5. **Pad rules (W3).** `pad.2` is a spacing rule (1.27 µm), not an opening size;
   no bond-pad opening size rule was found. CELL.4 therefore cannot be sourced
   from the PDK; it is a shuttle / package item.
6. **Tool state (L3, U1).** klt now extracts eight diode classes; thick-oxide
   marker rules are disclosed as not enforced; a rail-continuity recipe exists.
   Latch-up and ESD are still unchecked. The three filed gaps are closed.

## 4. Engineering and market arguments

These are arguments to weigh, not findings. No market data was gathered; the
need is taken from this repo's stated purpose.

- **For drawing every cell (record 0001).** The block exists to exercise thick-
  oxide, guard-ring, latch-up, ESD and seam rules with new geometry. Adopting a
  foundry cell exercises none. The foundry cell stays a comparison oracle.
  *Against:* the foundry `gpiov2` already provides more function than this
  proposal asks for; the canary's value is the tooling friction it finds, so a
  smaller target is acceptable only if the first cell still reaches the pad
  boundary and ring seam.
- **For 3.3 V VDDIO with 1.8 V core.** It sits inside the foundry range and the
  5 V devices' model validity with margin, and it is the case most users of the
  open PDK meet. *Against:* it does not stress the over-voltage case; the
  5.5 V stretch is the only row that would, and there is no foundry `gpiov2`
  precedent for it.
- **For a diode-plus-RC-clamp ESD topology.** It matches the foundry's documented
  rail-based approach and keeps paths in the regime the models cover. *Against:*
  the pad-positive-to-VSS path crosses two elements (diode, then clamp) and the
  reverse supply paths run through clamp body diodes; whether that is acceptable
  is the open G5 question.
- **For 75 corners.** A fixed named set makes results comparable. *Against:*
  cost; the 27-corner fallback is retained in PVT.5 and any multi-corner run goes
  through `klt sim` on the batch fleet.

## 6. Upstream tracking

The three issues filed for this work (klayout-tools #3802, #3803, #3804) are
closed, each by a narrower change than the title asked for. The remaining gap
is that **no klt sky130 deck checks latch-up or ESD layout rules**. #3802 is
closed, so a *new* tool-gap report would be needed to track it. This review
did not file it: the ruling says to track against existing issues and not to
duplicate, and the closed issue's thread ends in a disclosure. The operator
should decide whether to reopen #3802 or file a fresh report.

## 7. Bounded validation and resource plan

Nothing below is authorised by this review.

1. **Read-only, no cost:** confirm W1 to W3 numbers against the pages; read the
   5 V corner files for G2.
2. **Single-corner probes (allowed locally by the host rules):** one ngspice
   run each for diode forward drop at the ESD.2 current, the RC clamp trigger at
   `tt_25C_nn`, and the power-up ramp for G6. Report each as a probe, not a
   recorded result.
3. **Not before ratification of 0004:** the nine-plus path simulations (P1 to P9,
   reverse paths) and any corner set. These are multi-corner and go through
   `klt sim` on the Spot batch fleet; a failed batch submit is reported, not
   run locally.
4. **First implementation milestone is unchanged:** one GPIO cell, one supply
   pair (VDDIO + VSS) and one corner, DRC / LVS clean, before the full ring or
   any stretch row.
